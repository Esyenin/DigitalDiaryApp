# DigitalDiaryApp

DigitalDiaryApp - локальное приложение-электронный дневник для преподавателя. Проект помогает вести учебные группы, студентов, расписание, занятия, посещаемость, оценки и комментарии к работе студентов.

В репозитории реализованы backend-слои приложения и локальный пользовательский интерфейс на PySide6. Точкой запуска приложения является `main.py`.

Основная документация проекта находится в разделе [docs](docs/source/index.md). В ней описаны продукт, предметная область, архитектура, локальная разработка, текущее состояние и API.

## Что умеет проект сейчас

- хранить структуру учебных данных через SQLAlchemy-модели;
- валидировать входные данные через Pydantic-схемы;
- выполнять CRUD-операции через сервисы сущностей;
- работать через единый `OrmService` как через фасад над ORM-слоем;
- покрывать ключевую логику тестами;
- вести файловое логирование.

## Основные сущности

В проекте уже описаны следующие сущности:

- `Group` - учебная группа;
- `Student` - студент;
- `Schedule` - запись расписания;
- `ScheduleGroupLink` - связь группы с расписанием;
- `Lesson` - конкретное занятие;
- `Attendance` - посещаемость студента на занятии;
- `Mark` - оценка студента за занятие;
- `Comment` - комментарий преподавателя к занятию студента.

Структура связей между таблицами дополнительно отражена в файле [app/DB_diagram.pdf](app/DB_diagram.pdf).

## Архитектура

Проект разделен на несколько слоев:

- `app/models` - ORM-модели базы данных;
- `app/schemas` - Pydantic-схемы для валидации данных;
- `app/services` - сервисы работы с конкретными сущностями;
- `app/services/ormservice.py` - единая точка входа в ORM-логику;
- `tests` - тесты моделей, схем, сервисов и ORM-фасада.

Интерфейс использует backend-слои приложения для работы с данными и прикладными операциями.

## База данных

PostgreSQL используется, если полностью заданы параметры подключения.

Если настройки PostgreSQL не заданы полностью, приложение автоматически переключается на локальную SQLite-базу. Это удобно для локального запуска, прототипирования и разработки без обязательного поднятия PostgreSQL.

Настройки читаются из файла `.env` в корне проекта.

Основные параметры:

- `DB_USER`
- `DB_PASSWORD`
- `DB_HOST`
- `DB_PORT`
- `DB_NAME`
- `SQLITE_DB_PATH` - имя или путь к локальному SQLite-файлу, если используется fallback

## Установка

1. Клонировать репозиторий:

```powershell
git clone https://github.com/Esyenin/DigitalDiaryApp.git
cd DigitalDiaryApp
```

2. Создать виртуальное окружение:

```powershell
python -m venv .venv
```

3. Активировать виртуальное окружение:

Для Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Для Windows cmd:

```cmd
.\.venv\Scripts\activate.bat
```

Для Linux:

```bash
source .venv/bin/activate
```

4. Установить зависимости:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

5. Создать файл `.env` в корне проекта.

Если хочешь работать через PostgreSQL, укажи в нем:

```env
DB_USER=your_user
DB_PASSWORD=your_password
DB_HOST=localhost
DB_PORT=5432
DB_NAME=digital_diary
```

Если PostgreSQL не настроен, можно не заполнять эти поля полностью. Тогда
проект автоматически переключится на SQLite и создаст локальный файл базы
данных.

При желании можно явно задать имя SQLite-файла:

```env
SQLITE_DB_PATH=digital_diary.db
```

6. Проверить, что установка прошла нормально:

```powershell
.\.venv\Scripts\python.exe -m pytest tests
```

## Логирование

В проекте есть настройка файлового логирования.

Имя файла лога формируется в формате:

`ГГГГ-ММ-ДД_ЧЧ-ММ-СС_УРОВЕНЬ.log`

Пример:

`2026-05-10_15-42-18_INFO.log`

Внутри логов время записывается с миллисекундами.

## Цель проекта

Цель DigitalDiaryApp - дать преподавателю удобный локальный инструмент для повседневной работы с учебным процессом: от ведения списка студентов и расписания до фиксации посещаемости, оценок и комментариев по каждому занятию.

Проект развивается с упором на три вещи:

- читаемость кода;
- масштабируемость архитектуры;
- понятность для дальнейшей поддержки и развития.
