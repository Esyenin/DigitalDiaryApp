(architecture-schemas)=
# Схемы данных

Раздел описывает Pydantic-схемы пакета `app.schemas`, применяемые для
нормализации и проверки данных перед передачей в сервисный слой.

Автоматическое описание классов доступно в API-справочнике. На этой
странице зафиксированы назначение вариантов схем, состав полей и правила
валидации.

## Общая организация

Для каждой предметной сущности предусмотрены следующие варианты:

| Вариант | Назначение |
|---|---|
| `BaseSchema` | Общий набор пользовательских полей сущности |
| `CreateSchema` | Проверка данных для создания записи |
| `FilterSchema` | Формирование условий поиска |
| `UpdateSchema` | Проверка частичного обновления |
| `DeleteSchema` | Формирование фильтра удаления |

Отдельные схемы чтения отсутствуют. После выполнения операций
`OrmService` возвращает ORM-объекты либо списки ORM-объектов.

## Базовая конфигурация

Все прикладные схемы наследуются от `AppBaseSchema`.

Единая конфигурация Pydantic задаёт:

| Параметр | Значение | Поведение |
|---|---|---|
| `extra` | `forbid` | Неизвестные поля отклоняются |
| `from_attributes` | `True` | Схема может создаваться из атрибутов ORM-объекта |
| `validate_assignment` | `True` | Присваивание нового значения повторно валидируется |
| `str_strip_whitespace` | `True` | Пробелы по краям строк удаляются |

Дополнительные базовые схемы:

| Схема | Поля |
|---|---|
| `IdSchema` | `id: int` |
| `TimestampSchema` | `created_at: datetime`, `updated_at: datetime` |

## Служебные поля

Служебными считаются:

```text
id
created_at
updated_at
```

Функция `strip_service_fields()` удаляет эти ключи из отображений,
переданных в схемы создания и обновления.

Если передан объект, не являющийся отображением, функция возвращает его
без изменений.

Это позволяет игнорировать идентификатор и временные поля при создании
или обновлении записи, не ослабляя общий запрет неизвестных полей.

## Общие функции валидации

### Проверка непустой строки

`validate_not_empty_string()` отклоняет значение `""`.

Значение `None` допускается там, где поле объявлено необязательным.
Предварительное удаление пробелов выполняется базовой конфигурацией
Pydantic.

### Проверка непустого отображения

`validate_non_empty_mapping()` требует, чтобы входные данные являлись
непустым отображением.

Проверка применяется к схемам обновления и удаления, чтобы исключить
операции без полей или без фильтра.

### Проверка явного `None`

`validate_not_none_fields()` проверяет только перечисленные поля и только
в том случае, если соответствующий ключ присутствует во входных данных.

Механизм используется для полей, которые допускаются в частичном
обновлении, но не могут быть явно очищены до `None`.

## Поведение вариантов схем

### Создание

Схемы создания:

- требуют обязательные пользовательские поля;
- применяют ограничения типов и длины;
- удаляют `id`, `created_at` и `updated_at`;
- отклоняют остальные неизвестные поля.

### Фильтрация

Схемы фильтрации:

- содержат пользовательские и служебные поля;
- делают поля необязательными;
- допускают построение фильтра по идентификатору и временным полям.

Пустая схема фильтрации в общем случае допустима и может означать выборку
без ограничивающих условий.

### Обновление

Схемы обновления:

- удаляют служебные поля;
- требуют хотя бы одно оставшееся поле;
- разрешают только изменяемые пользовательские поля;
- для отдельных сущностей запрещают явный `None` в обязательных по смыслу
  полях.

### Удаление

Схемы удаления:

- допускают пользовательские и служебные поля;
- требуют непустой фильтр;
- предотвращают удаление без явно переданного критерия.

## Учебная группа

### Состав схем

| Схема | Поля |
|---|---|
| `GroupCreateSchema` | обязательное `name`; необязательное `speciality` |
| `GroupFilterSchema` | `id`, временные поля, `name`, `speciality` |
| `GroupUpdateSchema` | `name`, `speciality` |
| `GroupDeleteSchema` | `id`, временные поля, `name`, `speciality` |

Ограничения длины:

| Поле | Максимальная длина |
|---|---:|
| `name` | 16 |
| `speciality` | 128 |

Пустые строки для `name` и `speciality` запрещены.

При обновлении `name` не может быть явно равен `None`.

При фильтрации и удалении поля `id` и `name`, если они присутствуют,
также не могут быть явно равны `None`.

### Вспомогательные проверки формата

Модуль содержит функции:

- `is_group_name_formatted()`;
- `is_speciality_formatted()`.

Они возвращают логический результат проверки шаблона, но не подключены к
основным валидаторам создания и обновления. Следовательно, соответствие
названия группы и специальности этим шаблонам не является обязательным
контрактом текущих схем.

## Студент

### Состав схем

| Схема | Поля |
|---|---|
| `StudentCreateSchema` | обязательные `group_id`, `surname`, `first_name`; необязательные `patronymic`, `personal_data`, `bmstu_email` |
| `StudentFilterSchema` | служебные и все пользовательские поля |
| `StudentUpdateSchema` | все пользовательские поля |
| `StudentDeleteSchema` | служебные и все пользовательские поля |

Ограничения длины:

| Поле | Максимальная длина |
|---|---:|
| `surname` | 128 |
| `first_name` | 128 |
| `patronymic` | 128 |
| `personal_data` | 16 |
| `bmstu_email` | 128 |

Пустые строки во всех строковых полях запрещены.

При обновлении поля `group_id`, `surname` и `first_name`, если они
переданы, не могут быть явно равны `None`.

Формат корпоративной электронной почты не проверяется специализированным
типом или отдельным валидатором.

## Расписание

### Состав схем

| Схема | Поля |
|---|---|
| `ScheduleCreateSchema` | обязательные `odd_or_even`, `type`, `day`, `time`; `is_assessment=False` |
| `ScheduleFilterSchema` | служебные и все пользовательские поля |
| `ScheduleUpdateSchema` | все пользовательские поля |
| `ScheduleDeleteSchema` | служебные и все пользовательские поля |

Ограничения длины:

| Поле | Максимальная длина |
|---|---:|
| `odd_or_even` | 16 |
| `type` | 64 |
| `day` | 16 |

Пустые строки для `odd_or_even`, `type` и `day` запрещены.

Допустимые значения чётности недели, вида занятия и дня недели не
ограничены перечислениями. Любая непустая строка подходящей длины проходит
валидацию.

## Связь группы с расписанием

### Состав схем

| Схема | Поля |
|---|---|
| `ScheduleGroupLinkCreateSchema` | обязательные `group_id`, `schedule_id` |
| `ScheduleGroupLinkFilterSchema` | служебные поля, `group_id`, `schedule_id` |
| `ScheduleGroupLinkUpdateSchema` | обновление запрещено |
| `ScheduleGroupLinkDeleteSchema` | служебные поля, `group_id`, `schedule_id` |

`ScheduleGroupLinkUpdateSchema` всегда выбрасывает `ValueError`.

Для изменения связи необходимо удалить существующую запись и создать
новую.

## Занятие

### Состав схем

| Схема | Поля |
|---|---|
| `LessonCreateSchema` | обязательные `schedule_id`, `date`; необязательное `topic` |
| `LessonFilterSchema` | служебные поля, `schedule_id`, `topic`, `date` |
| `LessonUpdateSchema` | `schedule_id`, `topic`, `date` |
| `LessonDeleteSchema` | служебные поля, `schedule_id`, `topic`, `date` |

Максимальная длина `topic` составляет 512 символов. Пустая строка
запрещена, значение `None` допускается.

Схема обновления принимает `schedule_id`, `topic` и `date`. При этом
текущий `LessonService` применяет не все принятые схемой поля одинаково;
данный контракт требует отдельной проверки на уровне сервисного слоя.

## Посещаемость

### Состав схем

| Схема | Поля |
|---|---|
| `AttendanceCreateSchema` | обязательные `student_id`, `lesson_id`; `is_visited=False` |
| `AttendanceFilterSchema` | служебные поля, `student_id`, `lesson_id`, `is_visited` |
| `AttendanceUpdateSchema` | обязательное `is_visited` |
| `AttendanceDeleteSchema` | служебные поля, `student_id`, `lesson_id`, `is_visited` |

Обновление изменяет только факт посещения. Связи со студентом и занятием
через эту схему не редактируются.

Текущая схема не поддерживает время опоздания, причину отсутствия и
подтверждающие материалы.

## Оценка

### Состав схем

| Схема | Поля |
|---|---|
| `MarkCreateSchema` | обязательные `student_id`, `lesson_id`, `data` |
| `MarkFilterSchema` | служебные поля, `student_id`, `lesson_id`, `data` |
| `MarkUpdateSchema` | обязательное `data` |
| `MarkDeleteSchema` | служебные поля, `student_id`, `lesson_id`, `data` |

Обновление изменяет только числовое значение оценки.

Минимальное и максимальное значение `data` схемой не ограничены.

## Комментарий

### Состав схем

| Схема | Поля |
|---|---|
| `CommentCreateSchema` | обязательные `student_id`, `lesson_id`; необязательное `data` |
| `CommentFilterSchema` | служебные поля, `student_id`, `lesson_id`, `data` |
| `CommentUpdateSchema` | только `data` |
| `CommentDeleteSchema` | служебные поля, `student_id`, `lesson_id`, `data` |

Максимальная длина `data` составляет 4096 символов.

Пустая строка запрещена. Значение `None` допускается и может
использоваться для отсутствующего текста комментария.

Обновление не позволяет изменить привязку комментария к студенту или
занятию.

## Сводная матрица обновления

| Сущность | Разрешённые поля обновления |
|---|---|
| `Group` | `name`, `speciality` |
| `Student` | `group_id`, `surname`, `first_name`, `patronymic`, `personal_data`, `bmstu_email` |
| `Schedule` | `odd_or_even`, `type`, `is_assessment`, `day`, `time` |
| `ScheduleGroupLink` | обновление запрещено |
| `Lesson` | схема принимает `schedule_id`, `topic`, `date` |
| `Attendance` | `is_visited` |
| `Mark` | `data` |
| `Comment` | `data` |

## Известные ограничения

### Связь ограничений с моделями

Схемы импортируют словари `MAX_LEN` непосредственно из модулей моделей.

Это обеспечивает единые ограничения длины, но создаёт зависимость слоя
валидации от слоя хранения.

### Неподключённые бизнес-правила

Текущими схемами не обеспечиваются:

- обязательный формат названия группы;
- обязательный формат специальности;
- формат электронной почты;
- перечисления допустимых значений расписания;
- диапазон оценки;
- перспективные правила моделей оценивания.

### Различие схемы и сервиса

Принятие поля схемой не гарантирует, что соответствующий сервис применит
его при обновлении.

Наиболее заметный случай — `LessonUpdateSchema`, допускающая изменение
`schedule_id`, `topic` и `date`, тогда как фактическое поведение
`LessonService` требует отдельного контрактного описания и тестирования.
