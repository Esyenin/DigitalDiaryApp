# Организация информации

Документация является частью проекта и должна изменяться вместе с
реализацией, требованиями и подтверждённым состоянием приложения.

Эта страница определяет, какой раздел считать основным источником конкретного
вида сведений и куда помещать новую информацию.

## Назначение документации

Документация проекта разделяет несколько видов информации:

- назначение и требования продукта;
- фактическое устройство текущей реализации;
- точные программные интерфейсы;
- процессы разработки и сопровождения;
- подтверждённое состояние проекта;
- структурированный контекст для автоматизированных инструментов.

Перспективные требования не должны представляться как существующая
реализация. Аналогично, особенности текущего кода не должны автоматически
рассматриваться как требования к будущему продукту.

## Канонический источник

При описании одного и того же объекта разные разделы отвечают на разные
вопросы.

Например, для `Student`:

- значение студента в предметной области относится к разделу
  [«О проекте»](../../project/index.md);
- фактические поля, связи и ограничения модели относятся к
  [«Архитектуре»](../../architecture/models.md);
- точное объявление Python-класса относится к
  [«API»](../../api/index.md).

Если необходимая информация уже подробно описана в каноническом разделе,
в другом месте следует дать только достаточный контекст и ссылку.

## Куда помещать новую информацию

Перед созданием или расширением страницы необходимо определить вид
добавляемой информации.

```text
Новое утверждение или описание
            │
            ├─ Требование, пользовательское понятие или назначение продукта?
            │      └─ О проекте
            │
            ├─ Описание фактического устройства текущего кода?
            │      └─ Архитектура
            │
            ├─ Нужна точная сигнатура класса, метода или поля?
            │      └─ API
            │
            ├─ Команда, процедура или правило сопровождения?
            │      └─ Разработка
            │
            ├─ Результат проверки, ограничение или известная проблема?
            │      └─ Состояние
            │
            └─ Инструкция или сокращённый контекст для ИИ-инструмента?
                   └─ Для ИИ
```

Если информация одновременно затрагивает несколько разделов, основной
факт размещается в каноническом разделе, а связанные страницы получают
краткие ссылки на него.

## Примеры выбора раздела

| Новая информация | Каноническое место |
|---|---|
| Добавлено новое перспективное требование к отчётам | О проекте |
| Изменена связь между `Group` и `Student` | Архитектура |
| Изменена сигнатура публичного метода сервиса | API |
| Изменена команда запуска приложения | Разработка |
| Изменился результат полного набора тестов | Состояние |
| Добавлено ограничение, которое должен учитывать ИИ-агент | Для ИИ |
