# Структура и навигация

Эта страница определяет структуру файлов документации, правила создания
подразделов и работу автоматической навигации.

## Структура страниц

Новая тема оформляется либо отдельной страницей, либо подразделом с
собственным `index.md`.

### Обычная страница

Самостоятельную тему, которая не требует нескольких документов, следует
размещать непосредственно внутри соответствующего раздела.

Пример:

```text
docs/source/development/testing.md
```

Такая страница автоматически обнаруживается навигацией раздела.

### Подраздел

Тему следует оформлять отдельным каталогом, если выполняется хотя бы одно
из условий:

- тема уже состоит из нескольких страниц;
- ожидается дальнейшее расширение темы;
- тема представляет самостоятельный сценарий или группу связанных сценариев;
- теме требуется собственная обзорная страница.

Пример:

```text
docs/source/architecture/workflows/
├── index.md
├── lesson-records.md
└── transactions.md
```

Внешняя навигация раздела подключает `workflows/index.md`. Внутренние
страницы подраздела организуются его собственной индексной страницей.

:::{admonition} Практическое правило
:class: note

Не следует создавать каталог ради одной короткой страницы без ожидаемого
расширения. Аналогично, крупную тему не следует превращать в один
чрезмерно длинный документ, если она естественно разделяется на несколько
самостоятельных страниц.
:::

## Автоматическая навигация

Для навигации внутри разделов используется пользовательская директива
`autotoctree`.

Пример:

```markdown
:::{autotoctree}
:hidden:
:maxdepth: 2
:titlesonly:
:order: models, schemas, services, ormservice
:::
```

Директива автоматически обнаруживает:

- страницы непосредственно внутри текущего раздела;
- вложенные подразделы, содержащие `index.md` или `index.rst`.

Страницы из параметра `:order:` размещаются первыми в указанном порядке.
Остальные обнаруженные документы добавляются после них в алфавитном
порядке.

Параметры директивы используются следующим образом:

| Параметр | Назначение |
|---|---|
| `:hidden:` | Дерево участвует в структуре сайта, но не выводится отдельным списком в содержимом страницы |
| `:maxdepth:` | Ограничивает глубину отображения вложенных документов |
| `:titlesonly:` | Использует в навигации заголовки документов |
| `:order:` | Задаёт фиксированный порядок ключевых страниц раздела |

Файлы и каталоги, имена которых начинаются с `_` или `.`, автоматической
навигацией не подключаются.

### Когда требуется `:order:`

Параметр `:order:` следует использовать только тогда, когда у основных
страниц существует естественная последовательность чтения.

Например, для архитектуры:

```text
Модели → Схемы → Сервисы → OrmService
```

Новые дополнительные страницы после этого могут подключаться автоматически.

Если естественного порядка нет, предпочтительно не задавать `:order:` и
оставить автоматическую сортировку.

## Имена файлов и каталогов

Имена файлов и каталогов документации должны:

- использовать латиницу;
- записываться в нижнем регистре;
- разделять несколько слов дефисом;
- отражать содержание страницы, а не внутреннее название задачи или коммита.

Рекомендуемые имена:

```text
models.md
lesson-records.md
data-exchange/
documentation.md
```

Не рекомендуется использовать:

```text
LessonRecords.md
lesson_records.md
Новая страница.md
task-17-final.md
```

Заголовок страницы при этом записывается нормальным русским языком:

```markdown
# Записи занятия
```

Названия классов, методов, схем и других программных идентификаторов
сохраняются в исходном виде:

```text
OrmService
LessonUpdateSchema
ScheduleGroupLink
```

## Служебные каталоги

Каталоги с именами, начинающимися с `_`, используются для инфраструктуры
документации и не считаются пользовательскими разделами сайта.

Текущая структура включает:

```text
docs/source/_ext/       пользовательские расширения Sphinx
docs/source/_static/    дополнительные CSS- и JavaScript-файлы
docs/source/_templates/ пользовательские шаблоны темы
```

Документы пользовательского содержания не следует помещать в эти каталоги.
