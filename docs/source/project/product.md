# Концепция продукта

## Назначение

DigitalDiaryApp — Электронный журнал для персональной работы преподавателя.

Приложение предназначено для организации учебной деятельности, оперативной
фиксации сведений во время занятий, хранения истории обучения и подготовки
отчётных документов.

Использование Электронного журнала должно сокращать количество рутинных
операций и снижать вероятность ошибок при ручном подсчёте результатов.

## Пользователь

Непосредственным пользователем приложения является преподаватель.

Один преподаватель может:

- вести несколько дисциплин;
- работать с несколькими учебными группами;
- хранить данные за несколько учебных лет;
- использовать приложение при работе в разных организациях;
- формировать отчёты для разных получателей.

Студенты не получают доступ к приложению и не взаимодействуют с ним
непосредственно.

Кураторы, сотрудники кафедры и иные лица могут получать сформированные
отчёты вне приложения.

## Режим работы

Электронный журнал проектируется как локальное приложение, способное
выполнять основные операции без постоянного подключения к интернету.

Обязательная авторизация не предусматривается. Доступ к журналу
определяется доступом к устройству и локальному хранилищу приложения.

Перенос данных между устройствами предусматривается следующими способами:

1. импорт и экспорт файлов;
2. создание и восстановление резервных копий;
3. перспективная синхронизация устройств через локальную сеть.

Синхронизация через локальную сеть требует отдельного проектирования и
не относится к подтверждённым возможностям текущей версии.

## Основные возможности

Целевая версия Электронного журнала должна обеспечивать:

- ведение учебных лет и семестров;
- ведение дисциплин;
- ведение учебных групп и списков студентов;
- составление расписания;
- регистрацию проведённых занятий;
- учёт посещаемости и опозданий;
- фиксацию оценок, баллов и иных результатов;
- ведение комментариев и событий;
- настройку правил оценивания;
- формирование семестровых и годовых отчётов;
- хранение истории за несколько учебных лет.

Импорт, экспорт, резервное копирование и синхронизация являются
обеспечивающими функциями. Они поддерживают работу журнала, но не
определяют его основное назначение.

## Учебные периоды

Учебный год является областью организации и архивирования данных.

Семестр является основным учебным периодом. Отчётность может
формироваться как за отдельный семестр, так и за учебный год в целом.

В пользовательском интерфейсе одновременно выбирается один активный
учебный год. Данные остальных лет сохраняются в хранилище и доступны
после переключения рабочего контекста.

## Загрузка данных

Выбор активного учебного года не означает загрузку всех его данных в
оперативную память.

Приложение должно получать из хранилища только сведения, необходимые для
открытого раздела и выполняемой операции.

Предполагаемый порядок сужения рабочего контекста:

```text
Активный учебный год
        ↓
Выбранный семестр
        ↓
Выбранная дисциплина или группа
        ↓
Необходимые занятия и результаты
```

Для работы с большими объёмами данных предусматриваются фильтрация
запросов, ограниченная загрузка связанных объектов и постраничное
отображение списков.

## Платформы и распространение

Целевыми платформами являются:

| Платформа | Предполагаемый способ распространения |
|---|---|
| Windows | установочный пакет |
| Linux | пакет приложения или переносимая сборка |
| Android | установочный пакет Android |

Сборки предполагается публиковать в GitHub Releases.

Поддержка платформы считается подтверждённой только после появления
воспроизводимой сборки и проверки приложения на соответствующей
операционной системе.

## Настройки отчётности

Карточки реквизитов являются независимой настройкой приложения.

Они не относятся к учебному году, семестру, дисциплине, группе или
занятию и не участвуют в ведении журнала.

Карточка реквизитов может содержать:

- ФИО преподавателя;
- наименование организации;
- факультет или кафедру;
- должность;
- контактные сведения;
- текстовые реквизиты;
- дополнительные пользовательские поля.

Карточка выбирается только при формировании отчёта.

Сформированный документ должен сохранять использованные реквизиты, чтобы
последующее изменение карточки не изменяло ранее подготовленные отчёты.

## Границы продукта

В целевую концепцию не входят:

- личные кабинеты студентов;
- просмотр журнала студентами;
- уведомления студентам;
- обязательный облачный сервис;
- управление пользовательскими ролями;
- интеграция с LMS;
- ведение общего расписания учебного заведения.

Электронный журнал остаётся персональным рабочим инструментом
преподавателя.
