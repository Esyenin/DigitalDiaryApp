# Состояние проекта

Страница объединяет зафиксированный baseline и автоматически вычисляемое
состояние основных компонентов проекта.

Автоматическая сводка пересчитывается при каждой Sphinx-сборке. Если после
принятой базовой точки обнаружены изменения кода, оценка соответствующих
компонентов автоматически становится более осторожной, пока состояние не
будет подтверждено вручную.

## Текущее состояние продукта

Таблица показывает пользовательские возможности, присутствующие в текущей
реализации. Наличие сценария в интерфейсе не означает автоматическое присвоение
статуса `PRODUCT VERIFIED`.

| Возможность | Текущее состояние |
|---|---|
| Недельное расписание | Реализован просмотр расписания с переходом между неделями |
| Группы | Просмотр, создание, изменение и удаление доступны в UI |
| Студенты | Просмотр, фильтрация по группе, создание, изменение и удаление доступны в UI |
| Шаблоны расписания | Создание, изменение и удаление доступны в UI; шаблон может быть связан с несколькими группами |
| Занятия | Формируются по шаблонам расписания в пределах настроенного семестра |
| Тема занятия | Просмотр и изменение доступны в UI |
| Посещаемость | Ввод и просмотр доступны в карточке занятия |
| Оценки | Ввод и просмотр доступны для занятий, помеченных как assessment |
| Комментарии | Ввод и просмотр доступны для студента на конкретном занятии |
| Статистика групп | Отображается в UI |
| Статистика студентов | Отображается в UI |
| Семестр | Реализован как настройка UI: дата начала и количество недель; отдельной ORM-сущности нет |
| Импорт XLSX | Доступен из UI, но подсистема имеет статус `REQUIRES AUDIT` и `KNOWN ISSUE` |
| Экспорт XLSX | Доступен из UI и относится к подсистеме `app/io_tools`, требующей отдельного аудита |
| Human table import | Реализация присутствует, но отдельный пункт меню скрыт |
| Multi-sheet smart import | Реализация присутствует, но отдельный пункт меню скрыт |
| Дисциплина как отдельная сущность | `PLANNED` |
| Полноценная модель академических периодов | `PLANNED` |

Будущие пользовательские сценарии и целевая предметная модель описаны в
разделе [Перспективные требования](../project/future.md).

## Baseline качества

| Python | `3.14.0` |

| Полный pytest | `1468 passed, 5 failed, 1 skipped` |
| Pylint backend | `9.94/10` |

Известные ошибки полного набора тестов относятся к подсистеме
`app/io_tools`, не включённой в подробный охват текущего архитектурного
аудита.

:::{admonition} Интерпретация автоматической оценки
:class: note

`TESTED` в сохранённом baseline означает подтверждённое состояние на момент
принятой базовой точки. Если соответствующий код изменяется после неё,
автоматическая оценка проверки сбрасывается до `UNVERIFIED`.

`PRODUCT VERIFIED` назначается только вручную после проверки сценария в
работающем приложении.
:::
